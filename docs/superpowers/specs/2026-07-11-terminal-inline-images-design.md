# Terminal inline images

## Goal

Allow terminal-visible text to embed a preprocessed raster image with an HTML-like
tag. The image must become coloured xterm cells so it scrolls, selects, and receives
the existing CRT effect exactly like all other terminal output.

## Authoring interface

Text emitted by any terminal command may include an inline image directive:

```text
<img src="/images/terminal/logo.png" width="32" alt="[ Adam Burmister logo ]">
```

- `src` is a same-origin, absolute public asset path.
- `width` is the rendered width in terminal columns. It is required and must be a
  positive integer that fits the active terminal width.
- `alt` is optional. It is written as plain text if the image cannot load or cannot
  be decoded; the fallback is `[image unavailable]` when it is omitted.
- Each directive must occupy a complete line. A directive mixed with ordinary text
  is emitted verbatim, rather than being partly parsed as an image.

Images are authored as small PNG assets, normally generated by:

```sh
npm run pixelate-image -- input.png public/images/terminal/logo.png --width 64
```

The script performs nearest-neighbour downscaling, preserving hard pixel edges.
`--width` is the output image width in source pixels. The terminal directive's
`width` independently selects its display size in character columns.

## Architecture

Introduce an `InlineImageRenderer` owned by the browser terminal adapter. It will:

1. Parse complete-line `<img>` directives from terminal writes.
2. Fetch and decode the referenced PNG in the browser.
3. Scale it to the directive width while preserving its aspect ratio and accounting
   for the terminal cell's approximately 2:1 character aspect ratio.
4. Emit two vertical pixels per xterm cell using `▀` and ANSI true-colour foreground
   and background colours. Transparent source pixels use the terminal's default
   background and retain no foreground colour.
5. Cache decoded source images for subsequent renderings in the session.

The adapter, not command implementations or individual file readers, owns
directive expansion. This makes it work for BBS ANSI files, virtual-file reads,
`cat`, `less`, static commands, and program output that uses `TerminalIO.write` or
`TerminalIO.writeln`.

`TerminalOutput.write` and `TerminalOutput.writeln` become promise-returning
operations, backed by one serialized output queue in `XTermAdapter`. Each operation
splits complete new-line-delimited content into lines and expands directives before
submitting the next item to xterm; ordinary text takes the same queue and retains
its order. Existing callers may safely ignore the returned promise, while content
loaders and interactive views await it when they must render a screen before they
capture input. The shell flushes the queue before printing its prompt or marking a
command finished, so an image cannot appear after its prompt.

The xterm buffer remains the single source of truth. `TerminalRendererSync` already
extracts true-colour foreground and background values, so no CRT-renderer changes
are necessary.

## Preprocessing script

Add `scripts/pixelate-image.mjs`, using the existing `pngjs` dependency. It accepts:

```text
pixelate-image <input.png> <output.png> --width <pixels>
```

The script validates its arguments, reads PNG input, calculates proportional height
with a minimum of one pixel, performs nearest-neighbour scaling, and writes the PNG
output. It exits non-zero with a concise message for unsupported input, missing
paths, or invalid widths. `package.json` exposes it as `npm run pixelate-image --`.

## Error handling and limits

- Only same-origin absolute paths ending in `.png` are accepted. Invalid markup is
  emitted verbatim so ordinary terminal text is never lost.
- Fetch, decode, and rendering failures emit `alt` text (or the standard fallback)
  and log a diagnostic to the browser console.
- A requested display width wider than the terminal is constrained to the available
  columns. Height is always computed from the constrained width.
- A maximum rendered height protects the terminal from oversized images; the image
  is proportionally reduced to fit it.
- Image rendering produces reset ANSI sequences after each row so image colours do
  not bleed into later text.

## Verification

- Unit-test directive parsing, including quoted attributes, missing optional `alt`,
  invalid sources, and non-directive text.
- Unit-test pixel-to-ANSI conversion for opaque, transparent, and odd-height images.
- Unit-test preprocessor dimensions and nearest-neighbour output with a small PNG
  fixture.
- Add a Playwright test that writes a directive through the terminal and asserts
  coloured cells reach the renderer sync path.
- Run `npm run check`, the focused tests, and `npm run build`.

## Out of scope

- JPEG, GIF, SVG, animation, remote image URLs, DOM/canvas overlays, and inline
  images embedded mid-line.
- Changing existing static content to use images; the feature is introduced with a
  documented example only.
